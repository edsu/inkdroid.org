In my [last post] I was waiting on a second CD-RW drive from eBay, hoping it would let John's TASCAM 788 export his songs to WAV. It arrived, and it half works. The 788 sometimes writes a disc and sometimes stops with the same PANIC message as before. At one point I deleted every song from the 788 except the one I was exporting, and that export worked, so I wondered if the 788 was running out of disk space. But then later exports failed anyway. After a lot of experimenting with two different drives I couldn't find any pattern to it, which was incredibly frustrating. I could hook the TASCAM 788 to an audio interface and get each track and mix off that way, but that would take even more time.

So I'm going back to the plan I mentioned at the end of the last post: rip the raw data from each CD, extract the audio as one long WAV file, and cut the tracks apart by hand in Audacity or another DAW. It means more manual work per song, but it doesn't depend on early-2000s hardware behaving itself.

Working on the ripping with Claude turned up a few things I'm glad we caught before imaging all the discs:

- My first images were scrambled. On macOS the regular disk device (`/dev/disk4`) goes through a cache that seems to mishandle these discs' 2352-byte sectors, and about a fifth of the sectors came back as copies of their neighbors. ddrescue still reported 100% rescued. Reading the raw device (`/dev/rdisk4`) fixed it.
- Each sector on a data CD carries its own address and a checksum, so a script can now check every sector of every image instead of trusting the ripping tool's percentage. A second copy made with cdrdao serves as a cross-check.
- When I first extracted audio from one disc it was all static. It turns out some of the discs hold 16-bit audio and some 24-bit, and on one the audio starts a byte later than the others. The extraction script now works out which is which, and plays me a few clips from each disc so I can hear that it's music before moving on.

The scripts, and notes on what I tried along the way, are in the [jas-discs] repository on GitHub.

Claude was a big help with all of this, though maybe not in the way I expected. It wrote most of the code, but some of its earlier code was part of the problem: the first version of the rip script had the two sector sizes backwards, and the first extraction script assumed every disc was 24-bit. What helped was its habit of checking the files instead of trusting what a tool reported. It read the address in every sector of an image that ddrescue said was perfect, and found the scrambling. When I said a WAV sounded like static, it measured which reading of the bytes looked like audio, and found the 16-bit discs. Once there was a check like that, I could trust the results, whoever (or whatever) wrote the code. And when it came down to whether something was music, the test was me listening.

The images, the audio, and a checksum manifest all go into a [BagIt] bag, so I'll be able to tell if anything changes when I copy them around later. I'm going to periodically upload the bags to a personal S3 bucket for safekeeping. Each disc gets four files, the raw image, ddrescue's map of what it read, the cdrdao copy, and the extracted audio:

```
backups/
├── bagit.txt
├── manifest-md5.txt
└── data/
    ├── exp_number_11.bin    134M
    ├── exp_number_11.map    462B
    ├── exp_number_11.raw    154M
    ├── exp_number_11.wav    133M
    └── ...
```

and the manifest lists a checksum for each of them:

```
d29a6bb44ad27e955ba8553c9286b6b0  data/exp_number_11.raw
1380e2112a41460c4529b4d3efba4cc0  data/exp_number_11.map
505669c9b4e7c25d41526185bcb86aa8  data/exp_number_11.bin
7cefcee860cf341689eff007b78cf85e  data/exp_number_11.wav
```

I've imaged 18 discs so far, and have about 80 to go. Then comes the slow (but fun) part: listening to each long WAV and finding where one track ends and the next begins. The tracks come out back to back, but the gaps between them vary, which is why my earlier script kept cutting songs in the wrong places. I'm not that experienced in using a DAW, so this should be another phase in the experiment. I've been wanting to have a practical project to learn [Ableton] which a lot of field recording and musicians I follow in Bandcamp seem to use. But it's kind of expensive so I might go with [Reaper] for now. If you have thoughts or opinions please get in touch.
