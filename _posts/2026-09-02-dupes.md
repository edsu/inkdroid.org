One of the strangest things about [RDF] is that it is a *data model* that can be
serialized using different data formats (XML, JSON, Turtle, n-triples etc).
Sometimes the same graph can even be expressed using the same data format in
different ways: e.g. different XML documents that produce the same RDF graph.

This plurality of serializations can often work to nudge users (of the data)
into a situation where they feel like they *MUST* use an RDF processing
library, even in cases where they would otherwise much rather reach for a more
familiar parsing library that is core to the language they are writing code in.

At work I'm part of a project where we are loading publicly available
[BIBFRAME] RDF data from the Library of Congress into a database. The database
is Postgres and we're storing the RDF as JSON-LD using Postgres' support for
JSON. As we are storing the JSON we [compact] and [frame] the JSON-LD so that
it has a *consistent* shape.

It is my hope that this processing will help make the BIBFRAME data more
accessible for people who aren't necessarily conversant in RDF. If they can
load the bibliographic description as JSON, and interact with it as JSON, like
they would from any Web based API then maybe they don't need to know about the
RDF data model behind it (unless they want to).

I believe that this approach to linked data is the spirit of [Rob Sanderson]'s
idea for [Linked Open Usable Data] (LOUD) which I think has a lot of merit, and
a track record of success in the uptake of the [IIIF] standard in cultural
heritage organizations.

Anyway, back to the different serializations...

Recently one of my colleagues noticed that we were seeing duplicate titles
show up in our user interface. As I started looking into why it became
clear that it wasn't a problem with our user interface, or with our data
loading, but with the original data itself.

If you are curious you can look at the [full record] as it appeared today.
There is *a lot* of detail there. To illustrate the problem I stripped out
everything (including the namespaces) to leave just the bare essentials needed:

```xml
<rdf:RDF>

  <!-- BIBFRAME Instance -->
  <Instance rdf:about="http://id.loc.gov/resources/instances/16900592">
    <title>
      <Title>
        <mainTitle>Kuang Shan tu zhi</mainTitle>
        <subtitle>si juan</subtitle>
      </Title>
    </title>
    <hasItem rdf:resource="http://id.loc.gov/resources/items/16900592"/>
  </Instance>

  <!-- BIBFRAME Item -->
  <Item rdf:about="http://id.loc.gov/resources/items/16900592">
    <itemOf>
      <!-- BIBFRAME Instance again -->
      <Instance rdf:about="http://id.loc.gov/resources/instances/16900592">
        <title>
          <Title>
            <mainTitle>Kuang Shan tu zhi</mainTitle>
            <subtitle>si juan</subtitle>
          </Title>
        </title>
      </Instance>
    </itemOf>
  </Item>

</rdf:RDF>
```

In this RDF XML you should be able to see the BIBFRAME `Instance` and `Item` are being described, and given a title. The `Item` and `Instance` are related via the `hasItem` and `itemOf` properties.

So here's the RDF XML represented in Turtle:

```turtle
<http://id.loc.gov/resources/instances/16900592>
    a Instance ;
    hasItem <http://id.loc.gov/resources/items/16900592> ;
    title [
        a Title ;
        mainTitle "Kuang Shan tu zhi" ;
        subtitle "si juan"
    ], [
        a Title
        mainTitle "Kuang Shan tu zhi" ;
        subtitle "si juan"
    ] .

<http://id.loc.gov/resources/items/16900592>
    a Item ;
    itemOf <http://id.loc.gov/resources/instances/16900592> .
```

If Turtle doesn't do it for you perhaps a visual representation of the graph will help:

<img src="/images/bibframe-duplicate.svg">

Hopefully you can see that the `Instance` resource has two duplicate titles?

The interesting thing about the XML is that the `Item` description actually
repeats the description of the `Instance`: it appears once at the root of the
XML document and again inside the `Item` itself. In principle this isn't a bad
thing to do. I'm guessing that LC are using this data in an XML processing context (not as an RDF
graph), and having the Instance title in the context of the Item is helpful for
display purposes.

But the problem arises because the `Title` element in the context of RDF
creates a [blank node] (a resource without identity). And since the
same `Instance` is being described twice with different `Title` resources, the
title becomes duplicated in the RDF graph. One nice feature of the RDF data
model is that duplicate statements (or triples) usually get flattened out. But
since blank nodes are involved this doesn't happen.

So the message here is: if you want people to be using your data as RDF (not
just XML) it's important to parse it as RDF and make sure the description says
what you think it says. Here the solution is simple and (I think) elegant:
remove the description of the Instance at the top level.

```xml
<rdf:RDF>
  <Item rdf:about="http://id.loc.gov/resources/items/16900592">
    <itemOf>
      <Instance rdf:about="http://id.loc.gov/resources/instances/16900592">
        <title>
          <Title>
            <mainTitle>Kuang Shan tu zhi</mainTitle>
            <subtitle>si juan</subtitle>
          </Title>
        </title>
      </Instance>
    </itemOf>
  </Item>
</rdf:RDF>
```

It says the same thing without the duplicate title.

How to ensure things are done correctly in JSON will need to wait for another post...
